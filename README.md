# transcribe

`pipeline.ps1` — основное решение в этом дистрибутиве. Скрипт принимает один входной аргумент и сам определяет, что ему передали: URL веб-страницы, URL `m3u8`-плейлиста, локальный `.mp3`-файл или локальный видеофайл. На выходе он всегда создаёт текстовую расшифровку в `.txt` и печатает путь к этому файлу в `stdout`.

Маршрутизация выполняется автоматически:
- страница -> извлечение плейлиста -> подготовка аудио -> транскрибация;
- плейлист -> подготовка аудио -> транскрибация;
- `.mp3` -> сразу транскрибация.
- видеофайл -> извлечение аудио в промежуточный `.mp3` -> транскрибация.

Если `pipeline.ps1` сам создаёт промежуточный `.mp3`, после успешной расшифровки этот файл удаляется. Если на вход подан пользовательский `.mp3` или видеофайл, исходный файл не удаляется.
Во время долгих операций скрипты показывают подробный этапный вывод и прогресс по основным фазам выполнения.

## Настройка окружения

### Требования

- Windows PowerShell 5.1+ или PowerShell 7+
- доступ в интернет
- `ffmpeg` и `ffprobe` в `PATH` для сценариев, где входом является URL плейлиста, страница или локальный видеофайл
- `python` в `PATH`, модуль `playwright`, Google Chrome или Microsoft Edge для сценариев, где входом является URL веб-страницы
- переменная окружения `OPENAI_API_KEY` для транскрибации

Установка `playwright` при необходимости:

```powershell
python -m pip install playwright
```

### Переменная `OPENAI_API_KEY`

Скрипт `transcribe.ps1`, который используется внутри пайплайна, читает API-ключ только из переменной окружения `OPENAI_API_KEY`.

На текущую PowerShell-сессию:

```powershell
$env:OPENAI_API_KEY = "ваш_токен_здесь"
```

Проверка:

```powershell
$env:OPENAI_API_KEY
```

На постоянной основе для пользователя:

```powershell
[Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "ваш_токен_здесь", "User")
```

После этого перезапустите терминал и снова проверьте:

```powershell
$env:OPENAI_API_KEY
```

## Запуск `pipeline.ps1`

Если URL содержит символы `&`, передавайте ссылку в кавычках. Иначе PowerShell может интерпретировать такую строку некорректно.

Вход — URL веб-страницы:

```powershell
./pipeline.ps1 "https://example.com/video-page"
```

Вход — URL `m3u8`-плейлиста:

```powershell
./pipeline.ps1 "https://example.com/video.m3u8"
```

Вход — локальный `.mp3`:

```powershell
./pipeline.ps1 .\audio\example.mp3
```

Вход — локальный видеофайл, например WebM:

```powershell
./pipeline.ps1 .\video\example.webm
```

Вход с диаризацией — разделением текста по спикерам:

```powershell
./pipeline.ps1 .\video\meeting.webm -wd
```

Вход с сохранением промежуточных файлов:

```powershell
./pipeline.ps1 .\video\meeting.webm -save
```

Ключи можно комбинировать:

```powershell
./pipeline.ps1 .\video\meeting.webm -wd -save
```

Для диагностики ошибок `ffmpeg`/`ffprobe` можно добавить `-DebugNative`:

```powershell
./pipeline.ps1 .\video\meeting.webm -wd -save -DebugNative
```

Поддерживаемые локальные видеоформаты: `.webm`, `.mp4`, `.mkv`, `.mov`, `.avi`, `.m4v`, `.wmv`.

Режим `-wd` использует модель `gpt-4o-transcribe-diarize`, запрашивает `diarized_json` и пишет итоговый `.txt` в формате:

```text
Спикер1: первая реплика
Спикер2: ответ
Спикер1: продолжение
```

Для диаризации учитываются два лимита: до 1400 секунд на один запрос модели и до 25 MB на upload-файл. Скрипт использует безопасные значения: чанки до 1300 секунд и целевой размер 24 MB.

Если запись в режиме `-wd` длиннее 1300 секунд, скрипт:
- ищет паузы через `ffmpeg silencedetect`;
- выбирает точки разреза рядом с идеальными равномерными границами;
- режет по тишине, если это не делает соседние чанки длиннее 1300 секунд;
- если подходящей тишины нет, режет по безопасной временной точке и пишет предупреждение в лог.

После выбора границ скрипт определяет самый длинный чанк, рассчитывает единый максимальный MP3-битрейт для всех чанков и кодирует их так, чтобы каждый был не больше 24 MB.

Первый чанк в режиме `-wd` отправляется без reference clips. Из ответа `diarized_json` скрипт выбирает до четырех первых спикеров, вырезает для них reference clips длительностью до 10 секунд и отправляет следующие чанки с `known_speaker_names[]` и `known_speaker_references[]`. Если позже найден новый спикер и reference clips меньше четырех, для него создается новый reference clip. Если спикеров больше четырех, references отправляются только для первых четырех.

Ключ `-save` сохраняет промежуточные файлы:
- промежуточный `.mp3`, который `pipeline.ps1` создал из видео, страницы или плейлиста;
- upload-файлы, чанки и reference clips, которые `transcribe.ps1` готовит перед отправкой в API.

Upload-файлы сохраняются рядом с итоговым `.txt` в папке вида `example_intermediate`. Если такая папка уже есть, создаётся новая с числовым суффиксом, например `example_intermediate_1`.

Ключ `-DebugNative` печатает подробную диагностику нативных команд и сохраняет stdout/stderr логи `ffmpeg`/`ffprobe` в intermediate-папке. Используйте его вместе с `-save`, если нужно отладить падение на этапе подготовки аудио.

Результат:
- на диске создаётся итоговый `.txt`;
- путь к `.txt` печатается в `stdout`;
- если `pipeline.ps1` сам создал промежуточный `.mp3`, этот файл удаляется после успеха.
- если на вход подан локальный видеофайл, итоговый `.txt` создаётся рядом с ним и получает то же базовое имя, например `example.webm` -> `example.txt`.
- во время выполнения на экране отображаются этапы работы и фазовый прогресс.

## Файлы дистрибутива

### `pipeline.ps1`

Главный входной скрипт дистрибутива.

Вход:
- URL веб-страницы;
- URL `m3u8`-плейлиста;
- путь к локальному `.mp3`-файлу;
- путь к локальному видеофайлу: `.webm`, `.mp4`, `.mkv`, `.mov`, `.avi`, `.m4v`, `.wmv`;
- опциональный ключ `-wd` для диаризации;
- опциональный ключ `-save` для сохранения промежуточных файлов;
- опциональный ключ `-DebugNative` для диагностики `ffmpeg`/`ffprobe`.

Выход:
- итоговый `.txt`-файл;
- путь к итоговому `.txt` в `stdout`.

Минимальный запуск:

```powershell
./pipeline.ps1 "https://example.com/video-page"
```

### `extract-playlist.ps1`

Служебный скрипт для извлечения `master m3u8` со страницы с видеоплеером.

Вход:
- URL веб-страницы.

Выход:
- один URL `master m3u8` в `stdout`.

Минимальный запуск:

```powershell
./extract-playlist.ps1 "https://example.com/video-page"
```

### `prepare-audio.ps1`

Служебный скрипт для получения аудио из HLS-плейлиста и сохранения его в `.mp3`.

Вход:
- URL `m3u8`-плейлиста;
- при необходимости: `-OutputFile`, `-MaxSizeMB`, `-MinBitrateKbps`.

Выход:
- `.mp3`-файл на диске.

Минимальный запуск:

```powershell
./prepare-audio.ps1 "https://example.com/video.m3u8"
```

### `transcribe.ps1`

Служебный скрипт для отправки `.mp3` в OpenAI Audio Transcriptions API и сохранения текстовой расшифровки.

Вход:
- путь к `.mp3`-файлу;
- при необходимости: `-WithDiarization` или коротко `-wd`;
- при необходимости: `-Save` для сохранения upload-файлов, пересжатых MP3 и чанков;
- при необходимости: `-DebugNative` для подробной диагностики нативных команд.

Выход:
- `.txt`-файл рядом с исходным `.mp3`;
- в режиме диаризации — форматированный текст с префиксами `Спикер1:`, `Спикер2:` и т.д.

Минимальный запуск:

```powershell
./transcribe.ps1 .\audio\example.mp3
```
